WORKFLOW VS BASIC AGENT

工作流智能体 vs 普通智能体

普通智能体
线性交互
  • 单一提示词驱动的问答模式
  • 无分支逻辑，处理流程固定
  • 适合简单问答、内容生成等直接任务
  • 开发门槛低，适合快速原型
工作流智能体
多节点编排
  • 多节点串联，支持条件分支与循环
  • 变量可在节点间传递与变换
  • 适合数据处理、多步骤自动化流程
  • 可视化画布拖拽，所见即所得

WHAT IS RAG

什么是知识库

RAG 原理

检索增强生成：文档向量化存储 → 用户提问时检索相关片段 → 注入 LLM 上下文 → 生成精准回答

三步流程

文档分段 → 向量嵌入 → 语义检索。将非结构化文档转化为可被 LLM 理解的知识片段

核心价值

让 LLM "学会"私有数据，解决知识截止和幻觉问题，实现基于真实文档的精准回答

CHUNKING STRATEGIES

分段策略

自动分段
智能切分
  • 系统根据文档结构自动判断分段边界
  • 按段落、章节等自然边界切分
  • 适合大多数场景，上手快、效果好
自定义分段
精细控制
  • 手动设定分段长度（如 500 tokens）
  • 配置重叠长度（overlap）保持上下文连贯
  • 自定义分隔符（如按 ## 标题切分 Markdown）
  • 适合专业场景，精细调优召回效果

RETRIEVAL STRATEGIES

检索策略配置

TopK

控制返回的文档片段数量，建议 3-5 条。过多引入噪音，过少信息不足

Score 阈值

最低相似度过滤，低于阈值不返回。建议 0.5-0.7 之间

重排序

Rerank 模型对初检结果二次排序，提升最相关片段排在前列

过滤条件

按元数据过滤文档，如只检索特定标签、特定来源的文档

API CALL EXAMPLE

API 调用示例

REST API 调用

向 Dify API 发送 JSON 请求即可获得 AI 回复，支持流式和非流式两种模式。

端点：POST /v1/chat-messages

参数：inputs（变量）, query（问题）, response_mode（streaming/blocking）

返回：JSON 格式的完整对话结果

流式响应 — response_mode: streaming 实现打字机效果

curl -X POST 'https://api.dify.ai/v1/chat-messages' \
  -H 'Authorization: Bearer app-xxx' \
  -H 'Content-Type: application/json' \
  -d '{
    "inputs": {},
    "query": "什么是RAG？",
    "response_mode": "blocking",
    "user": "user-001"
  }'

# 返回示例
{
  "answer": "RAG是检索增强生成...",
  "conversation_id": "abc-123"
}
