**交互说明**:

| 操作 | 触发方式 | 行为 |
|------|---------|------|
| 创建部门 | 点击右上角「+ 创建部门」 | 弹出创建部门对话框 |
| 展开/折叠 | 点击部门名称前的 ▼ 图标 | 展开/折叠子部门 |
| 管理部门 | 点击「管理」按钮 | 跳转到部门详情页面 |
| 删除部门 | 点击「删除」按钮 | 弹出确认对话框，检查是否有数据（默认部门不可删除） |
| 搜索部门 | 在搜索框输入 | 实时过滤部门列表 |

**按钮权限控制**：

| 按钮 | 租户管理员 | 部门管理员 |
|------|-----------|-----------|
| + 创建部门 | 可见 | **隐藏** |
| 管理 | 可见 | 可见（本部门及子部门） |
| 删除 | 可见（默认部门禁用） | **隐藏** |
| 编辑部门信息 | 可见 | **隐藏** |

**部门管理员的权限范围**：
- 可以看到和管理本部门及子部门
- 不能创建新部门
- 不能删除部门
- 不能编辑部门信息
- 可以创建成员到本部门及子部门
- 可以编辑本部门及子部门成员的信息（除租户角色和部门管理员外）
- 可以移出本部门及子部门成员（不能移出自己）

│  ┌─────────────────────────────────────────────────────────────────────┐   │

│  └─────────────────────────────────────────────────────────────────────┘   │
│  (租户管理员: 所有角色; 部门管理员: 只能选择 editor/normal/dataset_operator) │
│                                                                             │
│  部门管理员                                                                 │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ ☐ 设为部门管理员                                                    │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│  (仅租户管理员可以设置部门管理员，部门管理员看不到此选项)                     │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ ℹ️ 创建成功后，系统将发送包含初始密码的通知邮件给该成员。            │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│                                              [取消]  [创建]                 │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

**字段权限控制**：

| 字段 | 租户管理员 | 部门管理员 |
|------|-----------|-----------|
| 姓名 | 可编辑 | 可编辑 |
| 邮箱 | 可编辑 | 可编辑 |
| 初始密码 | 可编辑 | 可编辑 |
| 所属部门 | 可编辑（所有部门） | 可编辑（本部门及子部门） |
| 租户角色 | 可选择所有角色 | **只能选择 editor/normal/dataset_operator** |
| 部门管理员 | 可设置 | **隐藏** |

**注意**：
- 部门管理员创建成员时，不能创建 owner 或 admin 角色的成员
- 部门管理员创建成员时，不能设置部门管理员身份
- 只有租户管理员可以创建 owner/admin 角色的成员和设置部门管理员
- 邮箱必须全局唯一，一个账户只能属于一个租户

## 交互设计规范

### 1. 权限控制

| 用户角色 | 可见功能 |
|---------|---------|
| 租户管理员 (owner/admin) | 所有功能：创建/编辑/删除部门、创建/管理所有成员、设置/取消部门管理员、转移数据、查看所有数据 |
| 部门管理员 | 创建/管理部门成员、查看本部门及子部门数据、编辑本部门及子部门成员角色、移出本部门及子部门成员（不能设置/取消部门管理员，不能移出自己，不能编辑租户角色） |
| 编辑者 (editor) | 查看本部门数据、创建/编辑本部门应用和知识库 |
| 普通成员 (normal) | 查看本部门数据、使用本部门应用 |
| 知识库操作员 (dataset_operator) | 查看本部门知识库 |

**注意**：
- 只有租户管理员可以设置/取消部门管理员
- 只有 owner/admin/editor 角色可以被设置为部门管理员（normal 和 dataset_operator 不可以）
- 部门管理员不能设置/取消其他部门管理员
- 部门管理员不能移出自己
- 部门管理员不能编辑成员的租户角色（如 editor、normal 等）
- 部门管理员创建成员时，只能选择 editor/normal/dataset_operator 角色
- 部门可以没有部门管理员（所有成员由租户管理员管理）

### 角色变更规则

1. **如果部门管理员的角色从 owner/admin/editor 变为 normal 或 dataset_operator，系统自动取消其部门管理员权限，并通知租户管理员**
2. 角色变更时，系统检查该用户是否是部门管理员
3. 如果是，自动设置 `is_department_admin = false`
4. 发送通知邮件给租户管理员，说明该用户因角色变更而失去部门管理员权限

### 部门变更规则

1. **如果部门管理员被移动到其他部门，系统自动取消其原部门的管理员权限，并通知租户管理员**
2. 成员移动时，系统检查该成员是否是部门管理员
3. 如果是，自动设置 `is_department_admin = false`
4. 发送通知邮件给租户管理员，说明该用户因部门变更而失去原部门的管理员权限

### 邮箱唯一性规则

1. **邮箱必须全局唯一**（一个账户只能属于一个租户，不能跨租户）
2. 创建成员时，系统检查邮箱是否已被其他租户使用
3. 如果邮箱已被使用，返回错误："邮箱已被其他租户使用"

### 部门管理员权限范围

1. **部门管理员可以看到和管理本部门及子部门的数据和成员**
2. **如果父部门和子部门都有部门管理员，各自管理各自的范围，不冲突**：
   - 父部门管理员可以管理所有子部门的成员和数据
   - 子部门管理员只能管理本部门的成员和数据
   - 两者的权限范围有重叠，但不会产生冲突

```

### 5. 响应式设计

| 屏幕尺寸 | 布局调整 |
|---------|---------|
| >= 1280px | 完整布局，侧边栏 + 主内容区 |
| 768px - 1279px | 侧边栏可折叠，主内容区自适应 |
| < 768px | 侧边栏隐藏，底部导航栏，主内容区全宽 |

### 6. 默认部门规则

1. 每个租户有且仅有一个默认部门（`is_default = true`）
2. 默认部门**不可删除**
3. 默认部门**可以重命名**
4. 新租户创建时自动创建默认部门
5. 数据迁移时，现有数据自动归属到默认部门
6. 默认部门的 `path` 格式为 `/租户ID/部门ID`
7. **默认部门不能有子部门**（前端创建部门时，父部门选择器中过滤掉默认部门）

### 7. 数据转移操作

**转移成员**：
- 在部门详情页面，点击成员卡片上的「移出部门」按钮
- 弹出转移对话框，选择目标部门
- 租户管理员可以选择租户内的任何部门
- 部门管理员可以选择本部门及子部门
- 部门管理员不能移出自己
- 确认后完成转移
- 如果转移的成员是部门管理员，系统自动取消其原部门的管理员权限，并通知租户管理员
- 转移前显示该成员创建的应用/知识库列表，提醒用户这些数据将留在原部门

**转移应用**：
- 在应用列表页面，点击应用卡片上的「更多」→「转移」
- 弹出转移对话框，选择目标部门
- 租户管理员可以选择租户内的任何部门
- 部门管理员可以选择本部门及子部门
- 确认后完成转移

**转移知识库**：
- 在知识库列表页面，点击知识库卡片上的「更多」→「转移」
- 弹出转移对话框，选择目标部门
- 租户管理员可以选择租户内的任何部门
- 部门管理员可以选择本部门及子部门
- 确认后完成转移

**注意**：
- 只有租户管理员和部门管理员可以执行数据转移操作
- 部门管理员只能转移本部门及子部门的数据
- 转移数据时，数据的 `department_id` 字段会更新
- 转移完成后，数据在新部门可见，在原部门不再可见

## 总结

本文档详细描述了 Dify 部门管理系统的 Web 功能页面与交互设计，包括：

1. **部门管理页面**：部门列表、创建部门、部门详情
2. **成员管理页面**：成员列表、创建成员、编辑成员
3. **应用列表页面**：按部门过滤、创建应用、转移应用
4. **知识库列表页面**：按部门过滤、创建知识库、转移知识库
5. **交互设计规范**：权限控制、状态反馈、确认对话框、空状态、响应式设计

**核心权限规则**：
- 租户管理员：拥有所有权限
- 部门管理员：可以管理本部门及子部门的成员和数据，但不能编辑租户角色和设置部门管理员
- 普通成员：只能查看和使用本部门的数据

**关键设计决策**：
- 默认部门不能有子部门
- 邮箱必须全局唯一
- 部门管理员创建成员时只能选择 editor/normal/dataset_operator 角色
- 成员移动后，其创建的数据留在原部门
- 如果父部门和子部门都有部门管理员，各自管理各自的范围
