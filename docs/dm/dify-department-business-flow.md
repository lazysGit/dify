## 总结

本文档详细描述了 Dify 部门管理系统的业务流程，包括：

1. **部门管理流程**：创建部门、删除部门
2. **数据转移流程**：成员转移、应用转移、知识库转移
3. **成员管理流程**：创建成员到部门、移动成员部门、设置部门管理员
4. **数据隔离流程**：应用数据隔离、知识库数据隔离
5. **权限检查流程**：部门权限检查、成员权限检查

**核心业务流程**：
- 创建部门：检查权限 → 填写信息 → 检查名称唯一性 → 检查父部门 → 检查层级深度 → 生成路径 → 保存
- 删除部门：检查权限 → 检查是否默认部门 → 检查是否有子部门 → 检查是否有成员 → 检查是否有应用 → 检查是否有知识库 → 执行删除
- 成员转移：检查权限 → 检查是否为本人 → 检查操作者权限 → 显示成员创建的数据 → 选择目标部门 → 更新部门 ID → 检查是否为部门管理员 → 取消管理员权限（如果是）→ 返回成功
- 创建成员：检查权限 → 选择目标部门 → 填写成员信息 → 检查邮箱唯一性 → 创建用户账户 → 关联到部门 → 发送通知邮件 → 返回成功

**关键设计决策**：
- 部门管理员可以移动本部门及子部门的成员
- 成员移动后，其创建的数据留在原部门
- 如果移动的成员是部门管理员，系统自动取消其原部门的管理员权限
- 邮箱必须全局唯一
- 部门管理员创建成员时只能选择 editor/normal/dataset_operator 角色
