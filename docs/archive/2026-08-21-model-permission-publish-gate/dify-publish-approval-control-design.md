## 1. 需求概述

当前系统的应用发布（`app_published_departments`）允许任何有编辑权限的用户发布到任意部门。需要新增权限门控：

1. **普通用户**：只能发布到自己所属部门（同部门其他用户可见）
2. **管理员**：可以发布到其他部门（租户管理员可发布到任何部门，部门管理员可发布到管辖范围部门）

---

## 2. 设计决策

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 审批类型 | 权限门控（非审批工作流） | 简单直接，无需通知系统和待审状态 |
| "管理员"定义 | 租户管理员 + 部门管理员 | 与现有部门权限体系一致 |
| "发布给自己" | 发布到自己所属部门 | 复用现有发布到部门流程，无需新概念 |
| 执行点 | Service 层检查 | 与现有 app_service / dataset_service 权限检查模式一致 |

## 4. 权限规则与执行点

### 4.1 权限规则

| 角色 | 可发布到的部门范围 | 检查方式 |
|------|-------------------|---------|
| owner / admin（租户管理员） | 任何部门 | 始终允许 |
| department_admin（部门管理员） | 本部门 + 所有子部门 | 目标部门 path 是否以用户部门 path 为前缀 |
| editor | 仅本部门 | 目标 department_id == 用户 department_id |
| normal | 仅本部门 | 目标 department_id == 用户 department_id |
| dataset_operator | 仅本部门 | 目标 department_id == 用户 department_id |

### 4.2 执行点

在 `AppPublishService.update_publish_departments()` 中添加权限检查：

```python
def update_publish_departments(
    app_id: str,
    department_ids: list[str],
    user: Account,
    tenant_id: str,
):
    """更新应用发布部门（带权限检查）"""

    # 获取用户信息
    user_department_id = DepartmentService.get_user_department_id(user.id, tenant_id)

    for dept_id in department_ids:
        _check_publish_permission(user, dept_id, user_department_id, tenant_id)

    # 权限通过，执行更新（现有逻辑不变）
    _do_update_publish_departments(app_id, department_ids, user.id)


def _check_publish_permission(
    user: Account,
    target_dept_id: str,
    user_dept_id: str,
    tenant_id: str,
):
    """检查用户是否有权发布到目标部门"""

    # 租户管理员：允许
    if user.is_admin_or_owner:
        return

    # 目标部门 == 用户部门：允许
    if target_dept_id == user_dept_id:
        return

    # 部门管理员：检查目标部门是否在管辖范围
    if DepartmentService.is_department_admin(user.id, user_dept_id):
        user_dept = DepartmentRepository.find_by_id(user_dept_id)
        allowed_dept_ids = [
            d.id for d in DepartmentRepository.find_by_path_prefix(user_dept.path)
        ]
        if target_dept_id in allowed_dept_ids:
            return
        raise ForbiddenError("部门管理员只能发布到管辖范围内的部门")

    # 普通用户：只能发布到本部门
    raise ForbiddenError("普通用户只能发布到自己所属部门，如需跨部门发布请联系管理员")
```

### 4.3 与现有系统的关系

```
+------------------------------------------------------------------+
|  现有机制（不变）                         新增机制                  |
+------------------------------------------------------------------+
|                                                                    |
|  app_published_departments              _check_publish_permission  |
|  --> 记录发布到哪些部门                 --> 发布前的权限门控        |
|                                                                    |
|  enable_site                            权限检查不改变              |

|                                                                    |
+------------------------------------------------------------------+
```

## 5. API 接口设计

### 5.1 可发布部门列表

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET | `/console/api/apps/{app_id}/publishable-departments` | 有编辑权限 | 获取当前用户可发布的部门列表 |

#### GET 响应示例

```json
{
  "departments": [
    {"id": "dept-uuid-1", "name": "技术部 > 前端组", "is_own_department": true},
    {"id": "dept-uuid-2", "name": "技术部 > 后端组", "is_own_department": false}
  ],
  "publish_scope": "department_and_subdepartments",
  "can_publish_cross_department": true
}
```

`publish_scope` 取值：
- `all`：租户管理员，可发布到任何部门
- `department_and_subdepartments`：部门管理员，可发布到本部门及子部门
- `own_department_only`：普通用户，仅本部门

### 5.2 现有接口修改

| 接口 | 修改内容 |
|------|---------|
| `PUT /console/api/apps/{app_id}/publish-departments` | 新增 Service 层权限检查（路径和请求体不变） |

| 操作 | owner/admin | department_admin | editor | normal | dataset_operator |
|------|:-----------:|:----------------:|:------:|:------:|:----------------:|
| 发布到任何部门 | Y | N | N | N | N |
| 发布到管辖范围部门 | Y | Y | N | N | N |
| 发布到本部门 | Y | Y | Y | Y | Y |
| 查看发布状态 | Y | Y | Y | Y | Y |
| 编辑发布部门 | Y | Y（管辖范围） | Y（本部门） | N | N |

## 8. 边界规则与错误处理

### 8.1 边界规则

| 场景 | 处理方式 |
|------|---------|
| 普通用户尝试发布到其他部门（API 直接调用） | 返回 403 Forbidden |
| 部门管理员尝试发布到管辖范围外部门 | 返回 403 Forbidden |
| 用户被移动到新部门 | 之前发布的记录保留，新部门发布权限按新部门计算 |
| 部门管理员被取消管理员身份 | 之后发布操作按普通用户权限处理 |
| 应用未发布到任何部门 | 探索列表不显示（现有行为不变） |
| 目标部门被删除 | 发布操作返回 404（现有行为不变） |

### 8.2 错误处理

| 错误场景 | HTTP 状态码 | 错误码 | 说明 |
|---------|:-----------:|--------|------|
| 普通用户跨部门发布 | 403 | `forbidden` | 权限不足 |

## 11. 测试策略

### 11.1 单元测试

**AppPublishService 权限检查测试**:
- owner/admin 发布到任何部门成功
- department_admin 发布到管辖范围部门成功
- department_admin 发布到管辖范围外部门返回 403
- editor 发布到本部门成功
- editor 发布到其他部门返回 403
- normal/dataset_operator 发布到本部门成功
- normal/dataset_operator 发布到其他部门返回 403

### 11.2 集成测试

- 端到端：普通用户发布应用 → 发布对话框仅可选本部门
- 端到端：部门管理员发布应用 → 发布对话框可选管辖范围部门

### 11.3 向后兼容测试

- 升级后现有发布记录不变

## 总结

本文档详细描述了发布审批权限控制功能的设计：

- 复用现有 `app_published_departments` 表，无新增表
- Service 层权限门控，按角色限制可发布的部门范围
- 三级权限：租户管理员（全部）、部门管理员（管辖范围）、普通用户（本部门）

**核心设计决策**:
- 权限检查在 Service 层执行，与现有代码模式一致
- 发布审批为权限门控（非审批工作流），简单直接
